Empezar en cinco minutos

  1. Copia el CSS del Anexo A. Es la única definición de tokens que existe.
  2. Lee las tres reglas que lo gobiernan todo:
    • El color dice qué tiene que hacer el usuario, no de qué categoría es algo. Solo dos estados llevan color de verdad.
    • El icono dice qué; el color, cuánto corre; el texto está a un gesto.
    • La ruta primero: nombre, fechas, ciudad y estado antes que cualquier efecto.
  3. Lee el Anexo J entero. Es una pantalla resuelta con todas las reglas aplicadas y anotadas: se aprende más rápido ahí que en las tablas. Luego, las medidas en el Anexo B y tu pantalla en el Anexo C.
  4. Antes de entregar, pasa la checklist de §19.4 y las tres pruebas de §5.10: escala de grises, prueba de un segundo y recuento de colores.

Si solo vas a leer una cosa, que sea el fragmento de instrucción de §19.5: con eso se diseña dentro del sistema sin haberlo leído entero.

Si eres un agente

Este documento viaja solo: no hay una persona al lado para preguntarle. Estas seis reglas resuelven todo lo que te vas a encontrar.

  1. Orden de lectura. §19 entero (precedencia, algoritmo, contrato, checklist) → Anexo A (los valores) → Anexo J (el patrón resuelto) → el Anexo C de la pantalla que te toque → las secciones §2–§18 cuando necesites el porqué de una regla.
  2. Los valores salen del Anexo A y de ningún otro sitio. Un color, un tamaño o una duración que no esté allí no existe y NO DEBE inventarse. La única otra zona con valores es §19.5, que los repite a propósito para poder pegarse suelto.
  3. Nombre de marca ≠ token. La prosa dice a veces «noche», «peltre» o «grafito»: son nombres de marca. La tabla de §5.1 los empareja con su token. En código se escribe siempre el token (fondo, terciario, sup-alta). En prosa, cuerpo.s equivale a --cuerpo-s.
  4. Si dos afirmaciones chocan, gana la de la sección de reglas (§2–§18) sobre un anexo, y el Anexo A sobre cualquier cifra suelta. Si el choque sobrevive, aplica la precedencia de §19.1 y deja constancia escrita del conflicto en tu entrega en vez de resolverlo en silencio.
  5. Lo que el documento no especifica, se deriva, no se inventa: el algoritmo de §19.2 dice de dónde. Si de verdad no hay de dónde derivarlo, la pieza sale con la marca [EXTENSIÓN — validar], igual que hace este documento.
  6. Antes de entregar, pasa la checklist de §19.4, la prueba en escala de grises, y —si puedes ejecutar código— el guardián del Anexo K sobre cualquier modificación que hagas de este documento.

2. Fundamento

2.1 Qué es y qué promete [CANON]

Un agregador de festivales de metal europeos con vocación de planificador. La promesa se puede decir en una frase: te decimos qué hay, cuándo, dónde, cuánto cuesta llegar y si aún puedes entrar. Todo lo demás es accesorio.

2.2 Los tres valores [CANON]

La ruta primero. El sistema sirve a quien viaja. Fecha, ciudad y estado antes que cualquier efecto. Si un recurso no ayuda a decidir un viaje, sobra.

Sin jerarquía de escena. Las diez familias se tratan igual. Un festival de cuatrocientas personas se presenta con la misma dignidad que uno de ochenta mil. El tamaño se describe, nunca se premia. Corolario duro: nada de puntuaciones, rankings, «lo más popular» ni clasificaciones entre usuarios.

Libre por diseño. Licencia gratuita de uso comercial en todo activo, formatos abiertos, autoalojado. Y datos que se pueden llevar: quien se va, se lleva su ruta.

2.3 Traducidos a diseño [DERIVADO]

Valor Consecuencia
La ruta primero El dato invariable (§12.1) manda sobre la composición. Funciona sin conexión (§15).
Sin jerarquía de escena Tamaño en barras, nunca en color. Orden cronológico. Ni tablas de clasificación ni rachas.
Libre por diseño Sin stock, sin tipografías de pago, sin iconos propietarios. Exportación de datos siempre disponible.

  4. Sin conexión no es opcional (§15).
  5. Sin cuenta obligatoria. Nadie se registra para mirar fechas.

4. Dirección creativa

Ritual 30 / Fanzine 70 [CANON]. El fanzine ocupa la página; el ritual protege los datos. El ritual —neutrales acromáticos, góticas, retícula— vive donde se compara y se decide.

Test de dosis. ¿Parece un cartel arrancado de un muro y aun así encuentras la fecha sin esfuerzo? Correcto. ¿Parece una web de venta de entradas? Falta carácter. ¿No sabes cuándo es el festival? Te has pasado.

Test de equilibrio [CANON]. Aléjate dos metros de la pantalla. Deberías ver tres pesos: la masa oscura del fondo, las superficies de las tarjetas y tres o cuatro puntos de color, no más. Si ves confeti, sobra color. Si no ves ninguno, no hay nada accionable y algo falla en el dato.

Repertorio de firma. Grano generado · filo · seis separadores · emblemas circulares · sello rotado · línea de ruta · nodo de cierre. Siete, y ninguno más.

5.0 Cómo leer esta sección

El color de FestRoute tiene tres papeles que no se mezclan:

Papel Qué hace Dónde vive
Superficie Construye el espacio: fondo, superficies, líneas, texto Neutrales, §5.1 y §5.2
Significado Dice qué tiene que hacer el usuario El código, §5.3
Interfaz Estados del control, no del dato Roles, §5.4
Materia Carácter de marca. No significa nada Metales, §5.5

Un valor nunca cruza de papel: un metal no puede indicar un estado, y un color del código no puede usarse para decorar.

Los valores viven en el Anexo A y solo allí. Esta sección da los nombres, el papel y la medición: contraste, croma y separación perceptual. Si un hex de aquí no coincidiera con el del Anexo A, manda el Anexo A, porque es lo que se ejecuta.

Dos nombres para lo mismo, a propósito. El token es lo que se escribe en código; el nombre de marca es lo que se dice hablando. sup-alta y grafito son el mismo color. En una regla CSS va siempre el token.

5.3 El código · qué tiene que hacer el usuario [CANON]

Dos acentos y una escalera. Solo dos estados llevan color de verdad; los grados de certeza se codifican con luminosidad, casi sin croma.

Token Le dice al usuario Contraste Noct. Contraste Fragua Croma
accion Actúa ya. Puedes comprar, guardar, añadir 7.44 4.91 0.165
bloqueado Olvídalo. Agotado, cancelado 3.50 relleno + bloqueado-borde · sobre-oscuro encima 7.73 sobre-oscuro encima 9.97 0.150
certeza-alta Fíate. Cartel cerrado 9.52 8.41 0.030
certeza-media Espera. Falta información 5.83 4.91 0.050
certeza-baja Aún nada. Solo hay fecha 3.31 3.36 0.012
aviso Mira esto. Novedad desde tu última visita 7.42 5.53 0.140

Por qué funciona, medido. accion tiene 3.5× más croma que certeza-media y 14× más que certeza-baja. La saliencia es relativa: si todos los colores están igual de saturados, ninguno destaca. En la v3.1.0 los cuatro estaban entre 0.094 y 0.126 —un rango de 1.34×— y por eso no resaltaba nada.

Por qué la escalera va en luminosidad. Anunciado, parcial y completo son tres grados de lo mismo, y un grado se lee mejor como cantidad que como categoría. Los peldaños están separados 0.133 y 0.141 de distancia perceptual, y la escala la distingue incluso alguien con acromatopsia total.

El suelo de contraste de estos colores es 3:1, no 4.5:1. Son iconos y bordes, no texto. Exigirles 4.5 los encajonaba en la mitad clara del espacio de color y aplanaba los dos canales que sirven para destacar. Por eso certeza-baja puede quedarse en 3.31.

5.6 Lo que no lleva color [CANON]

El género se escribe en un parche: Mono 700, versales, +0.14em, texto primario, borde linea-fuerte, fondo base, radio 0. Diez familias —nombradas en el Anexo D.0—, cero colores. Se lee igual de rápido, aguanta el blanco y negro y no compite con el código.

El tamaño de festival va en una a cuatro barras de 2 px más el nombre escrito. Descriptivo, nunca jerárquico, y sin color.

5.7 Dosificación [CANON]

  • En un listado, un solo color por fila: el estado principal. Fuera de listado, máximo dos colores del código a la vez.
  • aviso y exito no entran nunca en un listado.
  • La sangre se derrama, no se escribe. bloqueado como texto sobre oscuro da 1.8:1. Va en relleno con sobre-oscuro encima: 7.73 en Nocturno, 9.97 en Fragua. hueso ya no vale aquí: en Fragua se vuelve oscuro para los títulos y sobre la sangre daría 1.82.
  • El botón primario lleva sobre-accion encima de accion: 8.03 en Nocturno, 5.30 en Fragua. Con fondo encima, Fragua se quedaba en 4.49 — por debajo de AA.
  • Seis significados es el techo. No se añaden colores al código.

5.9 Cómo se consume

Siempre desde la capa semántica, nunca desde un primitivo:

/* correcto */
.pastilla-venta { color: var(--accion); border-color: currentColor; }
.campo--error   { border-color: var(--error); }

/* incorrecto: apunta a un primitivo y se salta el tema */
.pastilla-venta { color: #FE8449; }

5.10 Cómo se verifica

Antes de entregar, tres comprobaciones, en este orden:

  1. Escala de grises. Si dos estados no se distinguen sin color, la pantalla no sale. El icono tiene que bastar.
  2. Prueba de un segundo. Mira una fila de la tabla durante un segundo. Si no sabes si puedes comprar, el acento no está haciendo su trabajo.
  3. Recuento de colores. En un listado, más de dos colores del código a la vez significa que sobra alguno.

6. Léxico icónico de estados

El cambio mayor de esta versión. En la interfaz densa —tarjeta, tabla, calendario y mapa— el estado se muestra solo con icono y color. El texto no desaparece: cambia de sitio.

6.1 La regla [CANON]

El icono dice qué. El color dice cuánto corre. El texto está a un gesto de distancia.

Cada estado tiene una silueta única, reconocible a 16 px y en blanco y negro. El color es refuerzo, nunca portador único del significado. Esto no es una concesión a la accesibilidad: es lo que hace que la pantalla siga funcionando a pleno sol, con brillo bajo o para el 8 % de hombres con daltonismo.

6.3 Cómo se muestra [CANON]

  • Un solo estado principal por objeto. Si coinciden varios, gana el que exija acción más urgente: bloqueado > accion > certeza-media > certeza-alta > terciario.
  • Tamaños: 18 px en tarjeta y ficha, 16 px en tabla, 14 px en marcador de mapa y barra de calendario.
  • Nombre accesible obligatorio. Todo icono de estado lleva aria-label con el nombre escrito. Sin excepción.
  • Tooltip al pasar el ratón y al recibir foco. En táctil, un toque sobre el icono lo abre; no se depende del hover.
  • Leyenda persistente. Toda vista densa lleva un control «¿Qué significan?» que despliega los nueve con su nombre. Va en la barra de control, siempre en el mismo sitio.
  • La ficha escribe el estado con letras. El icono solo manda donde hay que comparar; donde se decide, se lee.
  • La primera visita muestra la leyenda abierta una vez y no vuelve a insistir.

6.4 Qué no se hace [DERIVADO]

NO DEBE usarse un icono de estado sin nombre accesible · NO DEBEN aparecer dos estados principales en la misma fila · NO DEBE cambiarse un icono de significado entre pantallas · NO DEBE reducirse por debajo de 14 px · NO DEBEN usarse emojis en ningún caso.

11.4 Internacionalización [CANON · v4.5.0]

La portada dice «multiidioma europeo» desde la v1 y hasta hoy no había ni una regla. Estas son, y casi todas se deducen de decisiones ya tomadas.

Qué se traduce y qué jamás. La interfaz se traduce entera. El dato, nunca: nombre de festival, banda, escenario, ciudad y topónimo se muestran como los escribe su dueño (§7.3 y §13.3). No existe «Praga» en la ficha de un festival checo: existe Praha, que es lo que pone en el andén.

La búsqueda perdona los diacríticos; la pantalla no. Escribir jaromer DEBE encontrar Jaroměř, y koln, Köln: el índice de búsqueda pliega diacríticos en las dos direcciones, consulta y dato. Pero el resultado se muestra siempre con su ortografía exacta. Plegar al buscar es cortesía con el teclado de quien viaja; plegar al mostrar es el error de dato de §7.3.

El alemán ocupa un tercio más. Toda pieza DEBE aguantar +35 % de texto sin romperse: el contenedor crece, el texto no se recorta. Un control jamás lleva puntos suspensivos — un botón truncado es un botón que no dice qué hace. El recorte con … solo se permite en contenido de datos (un nombre de festival kilométrico en una celda), siempre con el nombre completo a un gesto (§6.1). Nada esencial DEBE depender de que el texto quepa en una línea.

Fecha, hora y semana.

  • Reloj de 24 horas, sin excepción. 18:30, nunca 6:30 PM, en cualquier idioma.
  • La fecha lleva el mes escrito: 10–13 ago 2027, en el formato del idioma activo. 10/08 está prohibido — para media Europa es agosto y para la otra media es octubre.
  • La semana empieza en lunes (ISO 8601) en el calendario y en cualquier selector. Producto europeo, canon europeo.
  • El año se omite si es el corriente y se escribe si no lo es.

Cifras y moneda. Separadores decimales y de millar del idioma activo, vía Intl.NumberFormat, en Mono tabular como siempre (§7.2). El precio se muestra en la moneda en que se vende la entrada; la conversión a la moneda del usuario PUEDE acompañarlo, marcada como estimación con la frase del Anexo F: «Es un cálculo nuestro, no un precio oficial».

Orden alfabético con colación local (Intl.Collator del idioma activo): Š no se ordena como una S rota, ni Ø al final de todo. El orden por defecto sigue siendo cronológico (§12.4); esto aplica cuando el usuario ordena por nombre.

Las cadenas no se pegan. Prohibido construir frases concatenando trozos: «Añadido» + «a tu ruta» sobrevive al español y muere en polaco. Cada mensaje es una clave completa con sus variables dentro, y los plurales siguen las reglas del idioma — el polaco tiene tres formas y el checo también; «1 festival(es)» no es una solución, es una rendición.

El idioma sigue al sistema y se cambia en Ajustes (§14.8), efecto inmediato y sin reiniciar. Alfabeto latino solo, como fija la portada: sin bidireccional ni escrituras no latinas en esta etapa, y se declara en vez de fingir que se soporta.

El tono viaja con el idioma. Las reglas de §11.1 y §11.2 —cálido con quien llega, directo con quien está dentro, el error que dice cómo seguir— DEBEN sobrevivir a la traducción. Se traduce la intención, no la sintaxis del español.

13.3 El mapa geográfico [CANON · v4.2.0]

La decisión

MapLibre GL JS como motor, teselas del basemap de Protomaps en formato PMTiles, autoalojadas, sobre datos de OpenStreetMap.

No es una preferencia estética. Sale de tres reglas que ya eran CANON y que eliminan casi todo el mercado por sí solas:

Por qué PMTiles y no un servidor de teselas [DERIVADO]. Un servidor responde millones de preguntas pequeñas; PMTiles empaqueta la pirámide entera en un solo archivo que el cliente lee por rangos de bytes. Tres consecuencias: el archivo es la descarga sin conexión, así que no hay que construir un mecanismo aparte para el modo recinto; no hay servidor que mantener, y un proyecto que se autoaloja por principio necesita que autoalojarse sea barato de operar; y cada nivel de zoom adicional dobla aproximadamente el tamaño, lo que convierte el zoom máximo en una decisión de producto.

Qué se autoaloja · REGLA DURA

Un mapa no son solo teselas. Los cuatro artefactos DEBEN servirse desde el dominio propio, o el mapa se rompe sin cobertura y filtra tráfico a terceros:

Artefacto Si falta
Teselas .pmtiles No hay mapa
Estilo style.json, en Nocturno y Fragua El mapa no es nuestro
Glifos .pbf por familia y rango Mapa mudo: sale sin un solo topónimo
Sprites Fallo de arranque en algunos motores, aunque no se usen

Las etiquetas del mapa van en Geist, con los glifos generados por nosotros. Ninguna decorativa entra en el mapa (§7.1). Los topónimos usan el campo de nombre local, nunca la versión inglesa: es §7.3 aplicado a la cartografía. Praha y Jaroměř, no Prague ni Jaromer. Un mapa que traduce los nombres deja de coincidir con los carteles de la carretera, que es justo cuando se usa.

El estilo · el mapa base es fondo, no dato [CANON]

El mapa base construye el espacio. Los únicos objetos con significado sobre él son los marcadores.

  • El mapa base se dibuja solo con neutrales. Ningún color del código entra en el estilo base.
  • Tres pesos, como el resto del sistema: agua y relieve al fondo, red viaria y fronteras en linea, topónimos en secundario. El agua es el único elemento que PUEDE llevar un croma mínimo, dentro de la banda fría de los metales (§5.5).

  • Nocturno por defecto también aquí, conmutado con el mismo control de sol y luna. El mapa NO DEBE quedarse en claro con el resto de la interfaz en oscuro.
  • Ni satélite, ni relieve sombreado, ni edificios en tres dimensiones.
  • Plano y con el norte arriba. Inclinación y rotación bloqueadas: girar el mapa rompe la lectura de los topónimos y no resuelve ninguna tarea de este producto.

14. La capa de usuario

Implementación: Anexo C · Especificación de pantallas

Toda esta sección es nueva. El principio que la ordena:

Local primero. Todo funciona sin cuenta y sin conexión. La cuenta solo sirve para sincronizar entre dispositivos y para aportar datos. Nada que el usuario haya guardado se pierde por no registrarse.

14.1 Cuenta y sesión [CANON]

Tres niveles de identidad:

Nivel Puede No puede

Colaborador Además, sus aportaciones entran con revisión ligera —

Reglas [DERIVADO]:

  • NO DEBE existir un muro de registro. Ninguna función de consulta o planificación pide cuenta.
  • La invitación a registrarse aparece como mucho una vez por sesión, en el momento en que aporta algo real: al crear la segunda ruta o al intentar aportar un dato. Nunca al entrar.
  • El estado de sesión se ve en un solo sitio: el icono user-circle de la barra.
  • Cerrar sesión no borra lo local, y se dice explícitamente en el diálogo.
  • Exportar siempre disponible, con o sin cuenta, en formato abierto. Quien se va, se lleva su ruta.

14.2 Alta y preferencias [CANON]

El alta es de tres campos como máximo y las preferencias se pueden saltar entero. Nada de asistentes de cinco pasos.

Preferencias que sí importan, todas opcionales y editables después: géneros favoritos (los diez, sin ordenar) · ciudad base · radio de viaje en km · presupuesto orientativo · medios de transporte disponibles · idioma, moneda y unidades.

Las preferencias filtran por defecto pero nunca ocultan: el usuario siempre ve cuántos resultados se han quedado fuera y con un toque los recupera. Ocultar sin avisar rompe sin jerarquía de escena.

14.3 Guardados y rutas [CANON]

Guardado es una marca simple: bookmark-simple, sin categorías ni carpetas.

Ruta es una secuencia con fechas. Un usuario PUEDE tener varias («Verano 2027», «Fin de semana en Praga»). Cada ruta muestra: festivales, días, kilómetros y coste de entradas, más los tramos entre paradas con transporte, tiempo y distancia.

Los tramos son el argumento del producto: ningún otro agregador dice cuánto hay de un festival al siguiente.

Conflictos: si dos festivales se solapan, la ruta lo marca con certeza-media y lo dice; no lo resuelve por su cuenta ni bloquea el guardado. El usuario decide.

Compartir: una ruta se comparte como enlace de solo lectura. No hay muros, no hay «regístrate para ver».

14.4 Comparador [CANON]

De dos a cuatro festivales en columnas, con las mismas filas que la ficha: fechas, ciudad, estado, aforo, precio desde, duración, cómo llegar, dónde dormir. Las diferencias se resaltan con peso, no con color: el color sigue reservado a los escenarios de decisión.

14.5 Presupuesto [EXTENSIÓN — validar]

Por ruta: entradas, transporte, alojamiento y un margen para gastos. Todo editable a mano, porque nuestras cifras son estimaciones y hay que decirlo. Cada cifra estimada lleva el icono warning-circle en terciario y su fuente en el tooltip.

14.6 Avisos [CANON]

Tres motivos, y ninguno más: salen entradas de un festival guardado · cambia el cartel de un festival de tu ruta · se cancela o aplaza algo tuyo.

Reglas duras: el usuario elige cuáles quiere y puede apagarlos todos · nada de avisos promocionales, recordatorios de vuelta ni «te echamos de menos» · como máximo uno al día agrupado, salvo cancelación, que es inmediata · el centro de avisos usa aviso para lo no leído y terciario para lo leído · un aviso siempre lleva al sitio exacto donde se puede actuar.

14.9.1 Los cuatro acabados [CANON]

La jerarquía no está en el color —eso sería un ranking— sino en el acabado, que es lenguaje de coleccionista. Se distinguen por forma, así que siguen siendo cuatro cosas distintas a 60 px y en escala de grises.

Los cuatro criterios describen al festival, nunca al usuario. Un garito de cuatrocientas personas puede llevar sello lacrado y un macro de ochenta mil llevar cosido simple. Eso es lo que mantiene intacto sin jerarquía de escena.

Por qué no la rampa de los MMO. Se valoró usar gris–blanco–verde–azul–morado, la de WoW, que este público lee sin pensar. Se descartó por tres motivos: su naranja legendario es nuestro accion, y un parche legendario se leería como «puedes comprar»; añadía seis colores a un sistema cuya tesis es la escasez; y la rareza ordena a las personas, que es justo lo que el segundo valor prohíbe. Nota de precisión, porque se confunden dos linajes: en WoW el legendario es naranja, no amarillo; el amarillo de rareza viene de Diablo, donde el azul es mágico y el amarillo raro. Adoptar los dos a la vez habría hecho que medio público leyera una cosa y medio otra.

Mis rutas completas · fichas de los festivales guardados · horarios descargados · el dato invariable de todo lo guardado · el mapa del recinto si existe · las entradas o códigos que el usuario haya guardado.

Lo que esta pantalla NO hace, a propósito

No usa metales, porque no hay ni emblema ni degradado de cabecera. No anima nada: una ficha es donde se decide, y ahí el sistema está quieto. No tiene sombras, porque en Nocturno la elevación es un escalón de superficie y una línea. Y no lleva un segundo botón primario, por muy tentador que sea poner «Comprar entradas» en naranja al lado de «Añadir a mi ruta».

El ejercicio que enseña más: ponla en escala de grises. Debe seguir sabiéndose que hay entradas a la venta, porque el ticket y la palabra lo dicen sin el naranja.

Nueve comprobaciones: versión coherente entre portada, título y pie · numeración sin huecos · ningún color definido en dos sitios fuera de las zonas libres · ningún icono por debajo de 14 px · todo $deprecated con versión de retirada · toda remisión a una sección o anexo que existe · el JSON parsea · toda referencia de token resuelve a una definición del Anexo A · los pares de contraste que el sistema promete se recalculan contra los hex reales, en los dos temas.

La octava existe porque en la v4.3.0 había tres referencias a bloqueado-txt, un token que nunca existió. La novena, porque en la v4.5.0 había cuatro cifras de contraste que no correspondían a ningún par real — y al estrenarla cazó la quinta: exito medido contra la superficie equivocada.

#!/usr/bin/env python3
"""
FestRoute · Yunque — guardián de coherencia del sistema de diseño.

Uso:  python3 validar.py 2026_08_06-FestRoute_Design_System-v4_3_0.md

Convierte la REGLA DE MANTENIMIENTO de §18 en algo que se cumple solo.
Nueve comprobaciones. Devuelve 0 si el documento puede publicarse.
"""
import json
import re
import sys
from collections import Counter

# Zonas donde un valor PUEDE repetirse, con su motivo escrito.
ZONAS_LIBRES = {
    "Anexo A": "es la definición de tokens",
    "19.5": "el fragmento se pega solo y por eso se autocontiene",
}


def zonas(texto):
    """Devuelve el texto partido en (nombre_de_zona, contenido)."""
    marcas = [(m.start(), m.group(1).strip())
              for m in re.finditer(r"^#{1,3} (.+)$", texto, re.M)]
    marcas.append((len(texto), "FIN"))
    return [(marcas[i][1], texto[marcas[i][0]:marcas[i + 1][0]])
            for i in range(len(marcas) - 1)]


def es_zona_libre(nombre):
    return any(z in nombre for z in ZONAS_LIBRES)


def c1_version(t, fallos):
    portada = re.search(r"^version:\s*([\d.]+)", t, re.M)
    titulo = re.search(r"^# .*v([\d.]+)", t, re.M)
    pie = re.search(r"Sistema «Yunque» v([\d.]+)", t)
    vs = {"portada": portada, "título": titulo, "pie": pie}
    leidas = {k: (v.group(1) if v else None) for k, v in vs.items()}
    if len(set(leidas.values())) != 1:
        fallos.append(f"1· La versión no coincide: {leidas}")


def c2_numeracion(t, fallos):
    subs = re.findall(r"^### (\d+)\.(\d+)(?:\.\d+)?", t, re.M)
    por_seccion = {}
    for sec, sub in subs:
        por_seccion.setdefault(int(sec), set()).add(int(sub))
    for sec, nums in sorted(por_seccion.items()):
        esperado = set(range(1, max(nums) + 1))
        faltan = esperado - nums - {0}
        if faltan:
            fallos.append(f"2· §{sec} tiene huecos de numeración: falta "
                          + ", ".join(f"{sec}.{n}" for n in sorted(faltan)))


def c3_hex(t, fallos):
    cuenta = Counter()
    for nombre, cuerpo in zonas(t):
        if es_zona_libre(nombre):
            continue
        for h in set(re.findall(r"#[0-9A-Fa-f]{6}\b", cuerpo)):
            cuenta[h.upper()] += 1
    repetidos = {h: n for h, n in cuenta.items() if n > 1}
    if repetidos:
        fallos.append("3· Colores definidos en más de un sitio fuera de las "
                      f"zonas libres: {repetidos}")


def c4_iconos(t, fallos):
    # Tamaños de icono declarados: "icono 15", "icono 13 px", "icono: 12px"
    patron = re.compile(r"icono[s]?\s*(?:de\s*)?(\d{1,2})(?:\s*px)?"
                        r"(?:\s*\(\s*\**(\d{1,2})\**\s*(?:en [^)]*)?\))?", re.I)
    for m in patron.finditer(t):
        n = min(int(g) for g in m.groups() if g)
        if n < 14:
            ctx = t[max(0, m.start() - 60):m.start() + 40].replace("\n", " ")
            fallos.append(f"4· Icono de {n} px, por debajo del mínimo de 14 "
                          f"(§6.4): …{ctx}…")


def c5_deprecated(t, fallos):
    for m in re.finditer(r'"\$deprecated":\s*("[^"]*"|true)', t):
        v = m.group(1)
        if v == "true" or not re.search(r"v?\d+\.\d+\.\d+", v):
            fallos.append(f"5· $deprecated sin versión de retirada: {v}")


def c6_referencias(t, fallos):
    secciones = {int(m) for m in re.findall(r"^## (\d+)\.", t, re.M)}
    anexos = set(re.findall(r"^## Anexo ([A-Z])", t, re.M))
    for m in set(re.findall(r"§(\d+)", t)):
        if int(m) not in secciones:
            fallos.append(f"6· Referencia a §{m}, que no existe")
    for m in set(re.findall(r"Anexo ([A-Z])\b", t)):
        if m not in anexos:
            fallos.append(f"6· Referencia al Anexo {m}, que no existe")


PARES_CONTRASTE = [
    # (texto/figura, fondo, mínimo) · el contrato de accesibilidad, ejecutable
    ("secundario", "fondo", 7.0), ("primario", "fondo", 7.0),
    ("hueso", "fondo", 4.5),
    ("accion", "fondo", 3.0), ("aviso", "fondo", 3.0),
    ("certeza-alta", "fondo", 3.0), ("certeza-media", "fondo", 3.0),
    ("certeza-baja", "fondo", 3.0),
    ("error", "sup", 4.5), ("exito", "sup-alta", 4.5),
    ("linea-fuerte", "sup", 3.0),
    ("sobre-accion", "accion", 4.5), ("sobre-oscuro", "bloqueado", 4.5),
    ("foco-1", "foco-2", 13.0),
]


def _lum(h):
    h = h.lstrip("#")
    r, g, b = (int(h[i:i + 2], 16) / 255 for i in (0, 2, 4))
    f = lambda c: c / 12.92 if c <= 0.03928 else ((c + 0.055) / 1.055) ** 2.4
    return 0.2126 * f(r) + 0.7152 * f(g) + 0.0722 * f(b)


def _ratio(a, b):
    la, lb = sorted((_lum(a), _lum(b)), reverse=True)
    return (la + 0.05) / (lb + 0.05)


def c9_contrastes(t, fallos):
    """Los pares de contraste que el sistema promete se recalculan contra
    los hex reales del Anexo A, en los dos temas. Las cifras del texto
    pueden mentir; estas no."""
    m = re.search(r"^## Anexo A[^\n]*$", t, re.M)
    fin = re.search(r"^## Anexo B", t, re.M)
    if not (m and fin):
        return
    zona = t[m.start():fin.start()]
    corte = zona.find('data-tema')
    temas = {"Nocturno": zona[:corte], "Fragua": zona[corte:]}
    base = dict(re.findall(r"--([a-z0-9-]+)\s*:\s*(#[0-9A-Fa-f]{6})", temas["Nocturno"]))
    for nombre, cuerpo in temas.items():
        vals = dict(base)
        vals.update(re.findall(r"--([a-z0-9-]+)\s*:\s*(#[0-9A-Fa-f]{6})", cuerpo))
        for fg, bg, minimo in PARES_CONTRASTE:
            if fg in vals and bg in vals:
                r = _ratio(vals[fg], vals[bg])
                if r < minimo:
                    fallos.append(f"9· {nombre}: {fg} sobre {bg} da {r:.2f}, "
                                  f"por debajo del mínimo {minimo}")


def c8_tokens(t, fallos):
    """Toda referencia var(--x) o {x} resuelve a una definición del Anexo A
    o a un tamaño tipográfico, o a un bloque del contrato."""
    m = re.search(r"^## Anexo A[^\n]*$", t, re.M)
    fin = re.search(r"^## Anexo B", t, re.M)
    if not (m and fin):
        fallos.append("8· No encuentro el Anexo A para leer las definiciones")
        return
    zona = t[m.start():fin.start()]
    defs = set(re.findall(r"--([a-z0-9-]+)\s*:", zona))
    for ref in set(re.findall(r"var\(--([a-z0-9-]+)\)", t)):
        if ref not in defs:
            fallos.append(f"8· var(--{ref}) no está definido en el Anexo A")
    bloques_contrato = set(re.findall(r'^  "([a-z]+)"', t, re.M))
    for ref in set(re.findall(r'"\{([a-z0-9-]+)\}"', t)):
        base = ref.split(".")[0]
        if ref not in defs and base not in defs and base not in bloques_contrato:
            fallos.append(f"8· {{{ref}}} del contrato no resuelve a un token del Anexo A")


def c7_json(t, fallos):
    for bloque in re.findall(r"```json\n(.*?)\n```", t, re.S):
        try:
            json.loads(bloque)
        except Exception as e:
            fallos.append(f"7· El bloque JSON no parsea: {e}")


def main():
    if len(sys.argv) < 2:
        print("Uso: python3 validar.py <documento.md>")
        return 2
    t = open(sys.argv[1], encoding="utf-8").read()
    # El guardián vive embebido en el Anexo K: no debe leerse a sí mismo.
    t = re.sub(r"```python\n.*?\n```", "```python\n(guardián)\n```", t, flags=re.S)

    if not fallos:
        print("Sin fallos. El documento puede publicarse.")
        return 0
    print(f"{len(fallos)} fallo(s):\n")
    for f in fallos:
        print(" ·", f)
    return 1


if __name__ == "__main__":
